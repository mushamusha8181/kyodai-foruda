# 巨大フォルダ (GiantFolder)

Version 0.13.0

Android 上に「画面いっぱいの巨大フォルダ」を作る、スマートフォン向けのランチャー型アプリです。小さい画面でも窮屈になりすぎないシンプル UI を優先しています。

## 主な機能

- 端末のランチャーに表示されるアプリを検索・複数選択して追加
- 縦 5 列 / 横 7 列を初期値とし、列数・アイコンサイズを設定可能
- ページ追加、左右スワイプ、ページ複製、ページごとの色
- 入れ子フォルダ、名前変更、ドラッグ&ドロップ、複数選択移動
- お気に入り、固定ドック（最大 6 個）、常設検索、非表示項目管理
- スマートフォルダ：最近使った / よく使う / 新規 / ゲーム / SNS（推定） / Google 系
- 整理アシスト：新規アプリ、30 日以上使用記録なし（使用状況アクセスがある場合の参考値）
- 通知バッジ：初期値は「●」。設定で現在のアクティブ通知件数に変更可能（未読数ではありません）
- 巨大フォルダからの起動回数と最終起動、Android の使用状況記録による参考値
- アプリアイコンの差し替え、背景画像、キーカラー、透明度、角丸
- フォルダロック、巨大フォルダ起動時の本人確認
- 配置・設定の JSON バックアップ / 復元
- 他アプリ起動中の「戻るベロ」
  - タップ：最近使った 5 個の簡易ランチャー
  - 内側へスワイプ：巨大フォルダ本体へ戻る
  - 左右位置、幅、高さ、透明度、上下位置を調整可能
- ベロが使えない場合の戻る補助通知
  - 「開く」「15/30/60 分後」「今回は通知しない」

## 小さいスマホ向け UI

- 360dp 幅以下、または 700dp 高以下ではコンパクト表示へ切り替え
- ヘッダー、検索、編集、ドック、ページ操作、アプリセル、設定画面を省スペース化
- メインのアプリグリッドは縦スクロール可能
- Android 15 / targetSdk 35 の edge-to-edge でも操作部がシステムバーに隠れないよう安全領域を適用
- 大きな背景画像・カスタムアイコンは必要サイズ付近へ縮小して読み込み、メモリ使用量を抑制

## 権限と制限

初回の `PermissionSetupActivity` から、必要な項目だけ Android の設定画面へ案内します。アプリ側から特別なアクセスを勝手に ON にはしません。

1. 通知（Android 13+）
2. 他のアプリの上に重ねて表示
3. 使用状況へのアクセス
4. 通知へのアクセス

- 使用状況・通知アクセスを許可しなくても基本のフォルダ/ランチャー機能は利用できます。
- 通知の数字は「未読数」ではなく、現在 Android に出ている対象通知の件数です。常駐通知やグループ要約は除外します。
- Android の仕様や相手アプリの設定により、戻るベロを重ねて表示できない画面があります。その場合はフォアグラウンドサービス通知または補助通知が戻り口になります。
- 「15/30/60分後」の再通知は正確なアラーム権限を要求しない方式です。端末の省電力状態によっては指定時間より遅れる場合があります。
- 背景・カスタムアイコン・バックアップは Storage Access Framework を使うため、写真/ストレージ全体への広い権限は要求しません。
- 端末内の「ランチャーに表示されない内部アプリ」まで列挙するための `QUERY_ALL_PACKAGES` は使いません。

## フォント

`assets/fonts/RiiTegakiNR.ttf` または `.otf` が存在すればアプリ全体に読み込みます。フォントファイル本体は同梱していません。存在しない場合は sans-serif にフォールバックします。

## ビルド

Android Studio でプロジェクトを開いて Debug APK をビルドできます。

システムに Gradle が入っている場合は macOS / Linux で次も利用できます。

```bash
./build_debug_apk.command
```

GitHub では `.github/workflows/build-apk.yml` が Java 17 + Gradle 8.9 で `:app:assembleDebug` を実行し、Debug APK を Artifact として保存します。

## v0.13.0 コード健康診断

- 外部アプリから戻った後に「戻るベロ」が残る状態を修正
- スマートフォルダから戻った場合も、戻る UI / 補助通知セッションを確実に終了
- 外部アプリ起動処理を `AppLaunchManager` に寄せ、オーバーレイ簡易ランチャー側の重複処理を削減
- 通知リスナーの連続更新をデバウンスし、常駐通知・自アプリ通知・グループ要約を除外
- 使用状況集計を短時間キャッシュし、同じ 30/90 日走査の重複を削減
- アプリ選択画面のランチャー列挙を `AppCatalog` に統合し、同じ列挙ロジックを削除
- 壊れた/古い配置データを読み込み時に修復し、その修復結果を永続化
- 複数削除はツリー走査と保存を 1 回にまとめ、重複処理を削減
- フォント探索をキャッシュ
- 背景画像・カスタムアイコンのフル解像度読み込みを廃止
- 通知バッジは初期値を「通知あり ●」へ変更し、数字表示は任意設定へ分離
- Android 15 の edge-to-edge による上端/下端の操作部被りを補正
- 画面回転時に戻るベロのサイズ・位置を再構築
- README の重複記載と古いバージョン表記を整理

- 非表示フォルダやロックフォルダの配下がグローバル検索から見えてしまう経路を遮断
- 画面再生成時にロックフォルダ内部へ直接復元されないよう保護
- 新規インストール直後で未起動のアプリを「30日未使用」と誤判定しないよう修正
- 使用状況サービスの取得自体に失敗した場合は「利用可能」と扱わず、誤った未使用判定を防止
- 巨大フォルダからアプリを起動した後は使用状況キャッシュを無効化し、スマートフォルダ再表示時の順序を更新
- 「最近使った」「よく使う」は上位30件に絞り、小画面での過剰なView生成を抑制
- 設定/外部アプリから戻るたびに配置JSONを再解析せず、実際に配置が変わった場合だけ再読込
- 戻るベロサービスと権限セットアップでは配置ツリーを読み込まない軽量DataStoreを使用
- 画面回転時に戻るベロの再生成へ失敗した場合、無駄なフォアグラウンドサービスを停止して補助通知へフォールバック
- カスタムアイコン選択をキャンセルしたときの古い対象IDを確実に破棄
- バックアップ復元は items 配列内の不正要素を拒否し、読み込みサイズも10MBに上限を設定
- Android 15 の安全領域はViewがWindowへ接続された後にも確実に再要求
- 通知バッジは一時データとしてメモリだけに保持し、通知のたびにSharedPreferencesへ書き込む無駄を削除
- 通知バッジ更新の連続処理を250msでまとめ、グリッド再描画回数を抑制
- バックアップから取り込む設定キーと型をホワイトリスト化し、壊れた値で列数やベロサイズが異常化しないよう範囲を補正
- ページ番号/ページ数にも上限を設け、破損バックアップで巨大配列や極端なレイアウトが発生する経路を防止
- 戻るベロの上下位置をシステムバー/画面切り欠きの安全領域内へ補正
- アプリ追加/アイコン選択の結果直後とonResumeで二重にグリッドを再描画していた処理を削減
